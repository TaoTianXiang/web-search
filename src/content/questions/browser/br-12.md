## 事件时序

```
HTML 解析完成
  → DOMContentLoaded     （DOM 就绪，不含图片/样式/iframe）
  → 所有资源加载完成
  → load                 （图片、样式、iframe 全部就绪）
```

| 事件 | 触发时机 | 是否等待资源 |
| --- | --- | --- |
| `readystatechange`（interactive） | 解析完成 | ❌ |
| `DOMContentLoaded` | DOM 树构建完成 | ❌ |
| `readystatechange`（complete） | 全部完成 | — |
| `load` | 所有资源加载完 | ✅ |
| `beforeunload` | 即将离开（可阻止） | — |
| `unload` | 正在卸载 | — |

```js
document.addEventListener('DOMContentLoaded', () => {
  // DOM 可用，可以查询元素、绑定事件
})

window.addEventListener('load', () => {
  // 图片、字体等资源已就绪
})

window.addEventListener('beforeunload', (e) => {
  if (hasUnsaved) {
    e.preventDefault()
    e.returnValue = ''   // 触发浏览器确认弹窗
  }
})
```

## 与脚本的关系

```html
<script src="a.js"></script>          <!-- 阻塞解析，DOMContentLoaded 延后 -->
<script src="b.js" defer></script>    <!-- 解析完成后、DOMContentLoaded 前执行 -->
<script src="c.js" async></script>    <!-- 下载完立即执行，可能打断解析 -->
```

执行顺序：

| 脚本 | 执行时机 | 与 DOMContentLoaded 的关系 |
| --- | --- | --- |
| 同步 | 解析到即执行 | 会延后 DOMContentLoaded |
| `defer` | 解析完成后，按顺序 | 在其之前执行 |
| `async` | 下载完立即执行 | 可能在之前或之后 |

```
解析 → defer 脚本依次执行 → DOMContentLoaded
```

## readyState

```js
document.readyState
// 'loading'       —— 正在解析
// 'interactive'   —— 解析完成，DOM 可用（对应 DOMContentLoaded 前）
// 'complete'      —— 所有资源加载完成（对应 load）
```

可以用它判断"现在绑定监听是否还来得及"：

```js
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', init)
} else {
  init()
}
```

这是很多第三方 SDK 的标准写法。

## 首屏优化该关注什么

**都不是**。首屏体验用 Core Web Vitals 衡量：

| 指标 | 关注点 |
| --- | --- |
| LCP | 最大内容元素何时渲染 |
| FCP | 首次内容绘制 |
| TTFB | 首字节 |

`load` 事件在图片很多时会很晚，与用户"看到内容"的时机并不对应：

```
用户已看到完整页面 (LCP 完成)
  ↓ 20 秒后
load 才触发（因为某个底部的懒加载图片很慢）
```

所以不要把"load 时间"当首屏指标。

## beforeunload 的正确用法

```js
// 只在真的有未保存数据时启用
let dirty = false

window.addEventListener('beforeunload', (e) => {
  if (!dirty) return
  e.preventDefault()
  e.returnValue = ''
})
```

::: warn beforeunload 的限制
1. 现代浏览器只在用户**有交互**后才会显示确认框
2. 不能自定义文案（出于安全考虑）
3. 移动端支持很差（多数浏览器直接忽略）

需要可靠保存时用 `visibilitychange` + `sendBeacon`：

```js
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    navigator.sendBeacon('/collect', data)
  }
})
```
:::

::: interview 面试视角
能说清"defer 在 DOMContentLoaded 之前执行、async 不确定"，并指出"load 不等于首屏完成"，说明你理解实际的性能时序。
:::
