## 对照表

| | Cookie | localStorage | sessionStorage | IndexedDB |
| --- | --- | --- | --- | --- |
| 容量 | ~4KB | ~5MB | ~5MB | 数百 MB+ |
| 同步性 | 同步 | **同步阻塞** | 同步阻塞 | 异步 |
| 生命周期 | 可设过期 | 永久 | 标签页会话 | 永久 |
| 跨标签 | 同域共享 | 同域共享 | 仅当前标签 | 同域共享 |
| 随请求发送 | ✅ 自动 | ❌ | ❌ | ❌ |
| 可被 JS 读取 | 除 HttpOnly | ✅ | ✅ | ✅ |

## Cookie 的属性

```http
Set-Cookie: sid=abc; Path=/; Domain=.example.com; Max-Age=86400; Secure; HttpOnly; SameSite=Lax
```

| 属性 | 作用 |
| --- | --- |
| `HttpOnly` | JS 无法读取，防 XSS 窃取 |
| `Secure` | 仅 HTTPS 发送 |
| `SameSite=Lax` | 顶层导航 GET 会带（现代默认） |
| `SameSite=Strict` | 跨站完全不带 |
| `SameSite=None` | 跨站都带，必须同时 `Secure` |

## 为什么 token 不该放 localStorage

```js
localStorage.setItem('token', jwt)   // ❌
```

原因：**同源下的任何 XSS 脚本都能直接读取**。而 `HttpOnly` Cookie 完全无法被 JS 访问。

| 存储位置 | XSS 可读 | CSRF 风险 | 推荐 |
| --- | --- | --- | --- |
| localStorage | ✅ 可读 | 低（需手动加头） | ❌ |
| 非 HttpOnly Cookie | ✅ 可读 | 高 | ❌ |
| HttpOnly Cookie | ❌ | 需 SameSite/Token 防御 | ✅ |

正确组合：**HttpOnly + Secure + SameSite=Lax** Cookie 存 session，配合 CSRF Token 防御。

## localStorage 的三个坑

```js
// 1. 同步阻塞主线程
localStorage.setItem('big', JSON.stringify(hugeArray))  // 大对象会掉帧

// 2. 只能存字符串，类型会丢失
JSON.parse('{"d":"2026-01-01"}').d  // 字符串，不是 Date

// 3. 不可跨域，子域之间无法共享
// 需要 postMessage 中转或统一到主域
```

## IndexedDB 的适用场景

```js
const db = await openDB('app', 1, {
  upgrade(db) {
    const store = db.createObjectStore('notes', { keyPath: 'id' })
    store.createIndex('byDate', 'date')
  }
})

await db.put('notes', { id: 1, content: '...', date: Date.now() })
const all = await db.getAll('notes')
```

适合：

- 离线应用（PWA）的大量数据
- 本地缓存接口响应（减少请求）
- 富文本 / 图片 Blob 存储
- 大数据集的本地检索（配合索引）

## 存储容量与配额

```js
// 查询配额
const { usage, quota } = await navigator.storage.estimate()
console.log(`${(usage / 1024 / 1024).toFixed(1)}MB / ${(quota / 1024 / 1024).toFixed(0)}MB`)

// 申请持久化（避免被浏览器自动清理）
await navigator.storage.persist()
```

::: warn 隐私模式下的行为
Safari 隐私模式曾对 localStorage 抛错（配额为 0）。写入时应 try/catch，失败时降级为内存存储。
```js
try { localStorage.setItem(k, v) } catch { /* 降级 */ }
```
:::
