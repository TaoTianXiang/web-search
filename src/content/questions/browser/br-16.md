## 方案总览

| 方案 | 原理 | 局限 |
| --- | --- | --- |
| CORS | 服务端声明允许的源 | 需要服务端配合 |
| 代理（devServer / Nginx） | 同源转发 | 需要运维支持 |
| JSONP | `<script>` 回调用全局函数 | 仅 GET，安全风险 |
| postMessage | 窗口/iframe 通信 | 需校验 origin |
| WebSocket | 独立协议 | 需鉴权 |
| document.domain | 共享主域 | 已废弃 |
| iframe + location.hash | 老方案 | 已不推荐 |

## CORS（标准方案）

```http
Access-Control-Allow-Origin: https://a.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true
Access-Control-Max-Age: 86400
```

```js
fetch('https://api.b.com/data', {
  credentials: 'include'   // 带 cookie 时必须
})
```

见第 58 题的完整链路。

## 代理

**开发环境**：

```js
// vite.config.js
server: {
  proxy: { '/api': { target: 'https://api.b.com', changeOrigin: true } }
}
```

**生产环境**（Nginx）：

```nginx
location /api/ {
  proxy_pass https://api.b.com/;
  proxy_set_header Host $host;
}
```

优势：请求从同源发出，彻底绕开浏览器限制，连 Cookie 都天然同域。中后台项目常用。

## postMessage

```js
// 父页面
iframe.contentWindow.postMessage({ type: 'ready' }, 'https://b.com')

// iframe 内
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://a.com') return   // 必须校验
  console.log(e.data)
})
```

用于：嵌入第三方组件、多窗口协作、微前端通信。

::: warn 必须校验 origin
```js
// ❌ 任何来源的消息都接受
window.addEventListener('message', (e) => { doSomething(e.data) })

// ✅ 白名单
if (!ALLOWED.has(e.origin)) return
```
不校验 origin 会引入新的 XSS 风险。
:::

## JSONP（历史方案）

```js
function jsonp(url, cb) {
  const name = `__jsonp_${Date.now()}`
  window[name] = (data) => {
    cb(data)
    delete window[name]
    script.remove()
  }
  const script = document.createElement('script')
  script.src = `${url}?callback=${name}`
  document.head.appendChild(script)
}
```

问题：

1. 只支持 GET
2. 无法感知 HTTP 错误（只能超时判断）
3. 执行任意脚本（如果服务端被污染，等于 XSS）

现代项目不应再使用。

## 生产环境的选择

```
B 端中后台 + 独立 API 域
  → 优先：反向代理（同域部署，Cookie 天然可用）
  → 备选：CORS + 精确的 Allow-Origin

C 端 + 第三方 API
  → 必须 CORS（无法控制代理）

嵌入第三方页面
  → iframe + postMessage（严格校验 origin）
```

::: tip 代理的隐藏成本
用代理后，前端无法直接看到真实响应头（如 `Set-Cookie` 的 Domain），需要额外配置 `proxy_cookie_domain`。排查 Cookie 问题时容易被忽略。
:::

::: interview 面试视角
能说清"CORS 是浏览器行为，服务端已经处理了请求"、"postMessage 必须校验 origin"、"代理可以彻底绕开但需要运维支持"，说明你有落地经验。
:::
