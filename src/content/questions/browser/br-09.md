## 简单请求（不预检）

同时满足三个条件：

1. 方法是 `GET` / `HEAD` / `POST`
2. 请求头仅限 `Accept`、`Accept-Language`、`Content-Language`、`Content-Type`（以及少数安全相关）
3. `Content-Type` 仅限：
   - `text/plain`
   - `multipart/form-data`
   - `application/x-www-form-urlencoded`

即使用了 `application/json`，也**不是**简单请求。

## 预检请求

任一条件不满足，浏览器先发 `OPTIONS`：

```http
OPTIONS /api/users HTTP/1.1
Origin: https://a.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: content-type, authorization
```

服务端响应：

```http
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://a.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 86400
```

`Access-Control-Max-Age` 决定预检结果缓存多久，能显著减少 OPTIONS 请求数量。

## 带凭据（Cookie）的跨域

```js
fetch('https://api.b.com/user', {
  credentials: 'include'   // 必须显式指定
})
```

服务端必须：

```http
Access-Control-Allow-Origin: https://a.com   ← 不能是 *
Access-Control-Allow-Credentials: true
```

Cookie 还需：

```
SameSite=None; Secure
```

::: warn 三个必须同时满足
1. 前端 `credentials: 'include'`
2. 服务端 `Allow-Credentials: true` + 具体 Origin（不能用 `*`）
3. Cookie 的 `SameSite=None; Secure`

缺任何一个，Cookie 都不会被发送或接收。
:::

## 常见错误

```js
// 1. 使用 * 同时带 credentials → 浏览器直接拒绝
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true   // 无效

// 2. 漏了自定义头
Access-Control-Allow-Headers: Content-Type   // 少了 Authorization

// 3. 预检没返回 2xx
OPTIONS 返回 404/500 → 预检失败 → 实际请求不会发出
```

## 排查步骤

1. Network 面板看是否有 OPTIONS 请求
2. 看 OPTIONS 的响应头是否包含所需字段
3. 看是否返回 2xx（必须）
4. 看主请求的响应头 `Allow-Origin` 是否精确匹配
5. 若带 cookie，检查三项配置
6. 检查是否有中间层（网关/CDN）改写了响应头

## 为什么预检不发实际请求

预检的作用是"先问服务端是否允许"，避免实际请求产生副作用（如删除数据）后再被拦截。这是安全设计。

但注意：**简单请求没有预检**，所以服务端必须对 GET/POST 也做鉴权，不能假设"没预检就是可信的"。

## 与 JSONP 的区别

| | CORS | JSONP |
| --- | --- | --- |
| 方法 | 全部 | 仅 GET |
| 错误处理 | 有状态码与错误 | 只能超时判断 |
| 安全 | 受控 | 执行任意脚本，风险高 |
| 现代使用 | ✅ | ❌ 仅用于极老系统 |

::: tip 开发环境的代理
```js
// vite.config.js
server: {
  proxy: {
    '/api': { target: 'https://api.b.com', changeOrigin: true }
  }
}
```
代理让请求从同源发出，绕过浏览器限制。但**生产环境仍需真正的 CORS 或同域部署**。
:::
