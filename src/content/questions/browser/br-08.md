## 同源的定义

协议 + 域名 + 端口三者完全相同。

| A | B | 同源 |
| --- | --- | --- |
| `https://a.com/x` | `https://a.com/y` | ✅ |
| `https://a.com` | `http://a.com` | ❌ |
| `https://a.com` | `https://a.com:8443` | ❌ |
| `https://a.com` | `https://b.a.com` | ❌ |

## 限制的是什么

关键：同源策略限制的是**读取**，不是**加载**或**发送**。

| 资源 | 能否跨域加载 | 能否读取内容 |
| --- | --- | --- |
| `<img>` | ✅ | ❌（除非 CORS 允许） |
| `<script>` | ✅ | ❌（只执行，不读源码） |
| `<link rel=stylesheet>` | ✅ | ❌（但会影响渲染） |
| `fetch` / `XHR` | ✅ | ❌ 默认不允许 |
| `<iframe>` | ✅ | ❌ 不能访问内部文档 |
| `<video>` | ✅ | 部分（Canvas 读像素会被污染） |

这就是为什么 CDN 的图片和 JS 可以跨域使用：

```html
<!-- CDN 图片：可以显示 -->
<img src="https://cdn.b.com/logo.png">

<!-- CDN 脚本：可以执行 -->
<script src="https://cdn.b.com/lib.js"></script>

<!-- 但如果要读取像素或源码，就需要 CORS -->
```

```js
// Canvas 读取跨域图片像素会被污染
const img = new Image()
img.src = 'https://cdn.b.com/a.png'
img.crossOrigin = 'anonymous'   // 声明需要 CORS
ctx.drawImage(img, 0, 0)
ctx.getImageData(0, 0, 1, 1)    // 不带 crossOrigin 时会抛 SecurityError
```

## 为什么要这样设计

加载跨域资源是**网页的基本能力**（否则无法引用任何外部资源）。但**读取**跨域资源会让攻击者窃取数据：

```js
// 若无同源策略
fetch('https://bank.com/api/balance').then(r => r.text())
// 恶意站点可直接读取你的余额
```

所以限制点在"读取响应"。

## CORS 的本质

CORS 是**放宽同源策略的机制**：服务端通过响应头声明"我允许哪些源读取我"。

```http
Access-Control-Allow-Origin: https://a.com
```

浏览器看到这个头，才把响应交给 JS。**服务端已经处理了请求，只是浏览器不让 JS 读**。

::: warn 最常见的误解
"CORS 报错说明请求没发出去"是错误的。POST 请求可能已经执行（如创建了订单），只是响应被浏览器拦截。所以幂等性问题要格外小心。
:::

## 其他跨域方案

| 方案 | 原理 | 局限 |
| --- | --- | --- |
| CORS | 服务端声明允许 | 需要服务端配合 |
| 代理（Nginx / devServer） | 同源转发 | 需要运维支持 |
| JSONP | `<script>` 回调用函数名 | 仅 GET，有安全风险 |
| `postMessage` | 窗口/iframe 通信 | 必须校验 origin |
| WebSocket | 不受同源限制 | 需自行鉴权 |
| `document.domain` | 共享主域 | 已废弃 |

## 为什么 WebSocket 不受限制

WebSocket 握手是 HTTP 请求，但之后是独立的协议帧。浏览器**不强制**同源，所以：

```js
// 任何站点都可以连到你的 WS 服务
new WebSocket('wss://api.example.com/ws')
```

因此必须在服务端做**来源校验与鉴权**（检查 `Origin` 头 + token）。

::: interview 面试视角
"同源策略限制读取而非加载"是核心。能解释"CDN 图片可显示但不能读像素"和"WebSocket 不受限制所以必须服务端鉴权"，说明你理解机制而非只背规则。
:::
