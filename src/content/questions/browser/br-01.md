## 阶段拆解

```
URL 解析 → 缓存查找 → DNS → TCP → TLS → 请求 → 响应
   → HTML 解析 → DOM/CSSOM → 渲染树 → 布局 → 绘制 → 合成
```

### 1. URL 与缓存

1. 判断输入是搜索词还是 URL
2. 查 HSTS 列表（强制 HTTPS）
3. 依次查：Service Worker → 内存缓存 → 磁盘缓存
4. 命中强缓存则直接使用，不发请求

### 2. DNS 解析

查询顺序：浏览器 DNS 缓存 → 系统 hosts → 系统 DNS 缓存 → 递归查询（根 → 顶级域 → 权威）。

一个域名一次查询就是一次 RTT，多域名会累加。优化：`dns-prefetch`、减少域名数量。

### 3. TCP 三次握手

```
Client ──SYN──────────► Server
Client ◄─────SYN-ACK─── Server
Client ──ACK──────────► Server
```

1 个 RTT 后可以传输。优化：`preconnect`、连接复用（keep-alive）。

### 4. TLS 握手

| 版本 | 往返 |
| --- | --- |
| TLS 1.2 | 2-RTT |
| TLS 1.3 | 1-RTT（首次）/ 0-RTT（会话复用） |

### 5. 发送请求

请求头含 Cookie、Accept、Cache-Control 等。Cookie 过大会显著增加请求体积。

### 6. 服务端处理

TTFB 主要成本在此。优化：CDN、SSR 流式输出、接口聚合。

### 7. 接收响应

HTML 流式到达即可开始解析，不必等全部下载完（流式渲染的基础）。

### 8. 解析 HTML

- 构建 DOM 树
- 遇到 `<link rel="stylesheet">`：**阻塞渲染**（不阻塞 HTML 解析）
- 遇到同步 `<script>`：**阻塞解析**（且会等待前面的 CSS 下载完成，因为脚本可能读取样式）
- `defer`：解析完成后按顺序执行
- `async`：下载完立即执行

### 9. 构建 CSSOM

与 DOM 合并为 Render Tree（只含可见节点，`display: none` 不计入）。

### 10. 布局（Layout / Reflow）

计算每个节点的几何位置与尺寸。

### 11. 绘制（Paint）

生成绘制指令（如何填充像素），按层记录。

### 12. 合成（Composite）

合成线程把图层栅格化并上屏。`transform` / `opacity` 在这一层处理，不占用主线程。

## 各阶段瓶颈与优化

| 阶段 | 瓶颈 | 优化 |
| --- | --- | --- |
| DNS | 首次解析 | `dns-prefetch`、减少域名 |
| 建连 | RTT 累积 | `preconnect`、HTTP/3、keep-alive |
| TTFB | 服务端慢 | CDN、缓存、流式 SSR |
| HTML 体积 | 首包过大 | 压缩、流式、减少内联数据 |
| CSS | 阻塞渲染 | 关键 CSS 内联、非关键异步加载 |
| JS | 阻塞解析 | `defer`/`module`、代码分割 |
| 布局 | DOM 规模过大 | 减少节点、虚拟列表 |
| 绘制 | 大面积重绘 | 减少阴影/模糊、提升合成层 |
| 合成 | 层过多 | 控制 `will-change` |

## 首屏时间的四段拆解

若 LCP 慢，按这四段定位：

```
TTFB + 资源加载延迟 + 资源加载时长 + 元素渲染延迟
```

| 段慢 | 对应的手段 |
| --- | --- |
| TTFB | 服务端缓存、CDN、边缘渲染 |
| 加载延迟 | 在 HTML 中直接写 img、preload、fetchpriority |
| 加载时长 | 图片格式（AVIF/WebP）、按需尺寸 |
| 渲染延迟 | 拆分长任务，减少阻塞脚本 |

::: interview 面试视角
流水账式回答（"DNS → TCP → HTTP → DOM..."）只能算及格。能把每个阶段和"可优化的指标"对应起来，才是高级回答。
:::
