## 三者关系

```
重排（Layout） → 必然触发重绘（Paint） → 可能触发合成（Composite）
重绘（Paint） → 不触发重排
合成（Composite） → 不触发前两者（仅 transform / opacity）
```

| 操作 | 触发 |
| --- | --- |
| 改变几何属性（宽高、位置、字体大小、display） | 重排 + 重绘 |
| 改变外观属性（颜色、背景、阴影） | 重绘 |
| `transform` / `opacity`（已提升图层） | 仅合成 |

## 触发回流的常见操作

```js
// 1. 几何属性
el.style.width = '100px'
el.style.padding = '10px'
el.style.fontSize = '20px'

// 2. 结构变化
parent.appendChild(newNode)
el.remove()
el.className = 'bigger'

// 3. 读取布局属性（强制同步布局）
const h = el.offsetHeight
const w = el.clientWidth
const r = el.getBoundingClientRect()
const s = getComputedStyle(el).height

// 4. 窗口变化
window.resize
```

注意第 3 类：**读取布局属性本身会触发回流**，因为浏览器必须保证返回值是最新的。

## 强制同步布局（layout thrashing）

浏览器的布局通常是**异步批量**的：多次写样式会合并到一次布局。但如果写入后立即读取，浏览器必须**立即**执行布局来返回正确值：

```js
// ❌ 每次循环都强制布局
for (let i = 0; i < items.length; i++) {
  const h = items[i].offsetHeight          // 读 → 强制布局
  items[i].style.height = h * 2 + 'px'     // 写 → 使布局失效
}

// ✅ 批量读、批量写
const heights = items.map((el) => el.offsetHeight)   // 全部读
items.forEach((el, i) => { el.style.height = heights[i] * 2 + 'px' })  // 全部写
```

Performance 面板会明确标记为 `Forced reflow`，这是最常见的性能问题之一。

## 优化手段

### 1. 脱离文档流

修改前先 `display: none`，改完再恢复，只触发两次回流：

```js
el.style.display = 'none'
// 大量修改
el.style.display = 'block'
```

或用 `DocumentFragment` 批量插入。

### 2. 使用 transform 替代位置属性

```css
/* ❌ 触发重排 */
.move { left: 100px; top: 50px; }
.move { margin-left: 100px; }

/* ✅ 只触发合成 */
.move { transform: translate(100px, 50px); }
```

### 3. 提升合成层

```css
.animated {
  will-change: transform;
  /* 动画结束后移除，避免常驻显存 */
}
```

### 4. 避免高频读写交替

用 `requestAnimationFrame` 把写操作集中到帧前：

```js
requestAnimationFrame(() => {
  el.style.transform = `translateX(${x}px)`
})
```

### 5. 减少 DOM 规模

节点越多，单次布局成本越高。长列表用虚拟滚动。

### 6. 避免使用会触发布局的属性

```css
/* 避免频繁读取这些（它们会让布局失效） */
offsetTop / offsetLeft / offsetWidth / offsetHeight
clientWidth / clientHeight
scrollTop / scrollWidth
getBoundingClientRect()
getComputedStyle()
```

::: warn 一个隐蔽的重排源
```js
// 读取 offsetWidth 后立刻修改 class，会触发两次布局
el.style.width = el.offsetWidth + 1 + 'px'
```
这是一种典型的"读写交替"写法，常见于动画与拖拽实现中。
:::

能说清"transform 走合成线程不进主线程"、"读布局属性会强制同步布局"，并给出批量读写的具体写法，就超过了平均线。
:::
