## 本质区别

| | XSS | CSRF |
| --- | --- | --- |
| 本质 | **注入**：不可信数据被当代码执行 | **借用身份**：诱导用户发起请求 |
| 是否需要读响应 | 需要（窃取数据/令牌） | 不需要（只要请求被执行） |
| 攻击目标 | 用户与站点数据 | 站点上的用户操作 |
| 防御核心 | 输出编码 + CSP | SameSite + Token + Origin 校验 |

## XSS 的三种类型

| 类型 | 路径 |
| --- | --- |
| 存储型 | 恶意内容入库，所有访问者中招 |
| 反射型 | 恶意链接参数被立即回显 |
| DOM 型 | 前端把不可信数据写入危险 sink |

```js
// DOM 型示例：URL hash 直接写入 innerHTML
el.innerHTML = decodeURIComponent(location.hash.slice(1))
// 攻击链接：https://a.com/#<img src=x onerror=alert(1)>
```

## 危险 sink 清单

```js
el.innerHTML = userInput
el.outerHTML = userInput
el.insertAdjacentHTML('beforeend', userInput)
document.write(userInput)
eval(userInput)
new Function(userInput)
setTimeout(userInput, 0)        // 字符串形式
location.href = 'javascript:' + userInput
```

框架对应物：

```jsx
<div dangerouslySetInnerHTML={{ __html: content }} />   // React
<div v-html="content" />                                 // Vue
```

## XSS 防御

```js
// 1. 按上下文转义
function escapeHtml(str) {
  return str.replace(/[&<>"']/g, (c) => ({
    '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;'
  }[c]))
}

// URL 上下文用 encodeURIComponent
const url = `/search?q=${encodeURIComponent(keyword)}`

// 2. 富文本必须白名单净化
import DOMPurify from 'dompurify'
el.innerHTML = DOMPurify.sanitize(richText, {
  ALLOWED_TAGS: ['p', 'b', 'i', 'a', 'code', 'pre'],
  ALLOWED_ATTR: ['href']
})

// 3. CSP
// Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'

// 4. HttpOnly Cookie（让 token 无法被脚本读取）
```

## CSRF 的三要素

1. 用户已登录（Cookie 有效）
2. 攻击者能构造请求
3. 浏览器自动携带 Cookie

```html
<!-- 攻击者页面 -->
<form action="https://bank.com/transfer" method="POST">
  <input name="to" value="attacker" hidden>
  <input name="amount" value="10000" hidden>
</form>
<script>document.forms[0].submit()</script>
```

## CSRF 防御分层

| 手段 | 原理 | 局限 |
| --- | --- | --- |
| `SameSite=Lax/Strict` | 跨站请求不带 Cookie | 老浏览器兼容 |
| CSRF Token | 攻击者无法获知令牌 | 需服务端会话存储 |
| 双提交 Cookie | 令牌同时放 Cookie 与 header | 子域可覆盖 Cookie 时失效 |
| 校验 `Origin` / `Referer` | 检查来源 | 可能被裁剪 |
| 二次验证 | 敏感操作要求密码 | 影响体验 |

```js
// 自定义头方案：跨域表单无法设置自定义头
fetch('/api/transfer', {
  method: 'POST',
  headers: { 'X-CSRF-Token': token },
  body
})
```

## 为什么 CSP 不能替代输出转义

CSP 是**纵深防御的一层**，不是银弹：

1. 允许的第三方脚本被攻陷时，CSP 无法阻止
2. 老项目难以一步到位上严格 CSP（通常需要 report-only 观察期）
3. 部分绕过手法（DOM clobbering、JSONP 端点、`unsafe-inline` 遗留）仍可利用
4. 业务可能允许部分内联脚本（如埋点），削弱 CSP 强度

正确姿势：**转义是主力，CSP 是兜底**。

::: tip 三者的关系
```
XSS 防御：输入校验 → 输出编码 → 严格 CSP → HttpOnly
CSRF 防御：SameSite → Token → Origin 校验 → 二次验证
传输安全：HTTPS + HSTS
```
:::
