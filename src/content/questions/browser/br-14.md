## 原理

利用事件冒泡：不在每个子元素上绑监听，而在共同祖先上绑一个，通过 `event.target` 判断来源。

```js
// ❌ 为 1000 个 li 各绑一个监听
items.forEach((li) => li.addEventListener('click', handler))

// ✅ 委托到父元素
list.addEventListener('click', (e) => {
  const li = e.target.closest('li')
  if (li && list.contains(li)) handler(li)
})
```

## 三个好处

| 好处 | 说明 |
| --- | --- |
| 减少监听器数量 | 1000 个元素只需 1 个监听，省内存 |
| 动态元素自动生效 | 新增的子元素无需重新绑定 |
| 方便统一销毁 | 组件卸载时只需移除一个监听 |

```js
// React 的合成事件本质上就是委托（挂到根容器）
<div onClick={...}>  // 内部只有一个根监听
```

## 不能委托的事件

不冒泡的事件无法委托：

| 事件 | 是否冒泡 |
| --- | --- |
| `focus` / `blur` | ❌（用 `focusin` / `focusout` 可冒泡） |
| `mouseenter` / `mouseleave` | ❌（用 `mouseover` / `mouseout`） |
| `load` / `error`（资源） | ❌ |
| `scroll`（元素上） | ❌（在 document 上冒泡到 window） |
| `DOMContentLoaded` | ❌ |

```js
// 需要捕获阶段监听才能"委托"不冒泡的事件
container.addEventListener('focus', handler, true)   // 捕获阶段可以
```

## 正确找到目标元素

```js
container.addEventListener('click', (e) => {
  // ❌ 只判断 e.target，点到内部图标就会失效
  if (e.target.tagName === 'LI') { ... }

  // ✅ 用 closest 向上找
  const item = e.target.closest('[data-id]')
  if (!item || !container.contains(item)) return

  console.log(item.dataset.id)
})
```

`container.contains(item)` 用于防止"从容器外冒泡进来"的意外情况（虽然同层冒泡一般不会，但嵌套组件时可能出现）。

## 性能注意

委托不一定总是更快：

```js
// 对高频事件（mousemove），委托减少了监听但每次事件仍要冒泡
container.addEventListener('mousemove', handler)

// 更好的做法：节流 + passive
container.addEventListener('mousemove', throttle(handler, 16), { passive: true })
```

对于 `scroll`，用 `passive: true` 能让浏览器立即滚动而不等待 JS 执行完毕。

## 在框架中的表现

| 框架 | 机制 |
| --- | --- |
| React | 合成事件，委托到根容器（17+ 是 root，16 是 document） |
| Vue | 直接绑定（编译后在元素上 addEventListener） |

Vue 不委托的原因：模板编译时已知道事件绑在哪个元素，直接绑定更简单，且能精确控制 `.stop` / `.prevent` 等修饰符。

::: warn 事件委托与 stopPropagation 的冲突
子元素上调用 `stopPropagation()` 会阻止事件到达委托层，导致委托失效。调试时如果发现"点了没反应"，先检查是否有中间层阻止了冒泡。
:::

::: interview 面试视角
能说出"focus/blur 不冒泡需用 focusin/focusout"、"scroll 用 passive 优化"、"stopPropagation 会破坏委托"，说明你实际排查过事件问题。
:::
