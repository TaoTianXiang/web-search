## 真实机制

规范中没有"提升"，真实行为是：**进入执行上下文时先创建绑定，再在特定时机初始化**。

```js
console.log(fn)  // [Function: fn] —— 已初始化
function fn() {}

console.log(a)   // undefined —— 已创建并初始化为 undefined
var a = 1

console.log(b)   // ReferenceError —— 已创建但未初始化（TDZ）
let b = 2
```

## 三类声明的时机

| 声明 | 绑定创建 | 初始化 | 赋值 |
| --- | --- | --- | --- |
| `function` | 进入作用域 | 同左（函数对象） | — |
| `var` | 进入作用域 | 同左（undefined） | 执行到赋值语句 |
| `let/const` | 进入作用域 | 执行到声明语句 | 同左 |
| `class` | 进入作用域 | 执行到声明语句 | 同左 |

## 同名冲突的处理

```js
// 函数声明 vs var：函数优先，var 的赋值会覆盖
console.log(f) // [Function: f]
var f = 1
function f() {}
console.log(f) // 1

// 多个同名函数声明：后者覆盖前者
function g() { return 1 }
function g() { return 2 }
g() // 2
```

## 块级作用域中的函数声明

ES6 规范中，块内的函数声明是**块级**的，但浏览器实现（Annex B）为了兼容，会额外创建一个 var 绑定：

```js
if (true) {
  function h() { return 1 }
}
typeof h // 'function'（Annex B 兼容行为）
```

在严格模式或模块中，行为会不同（`h` 在块外不可见）。这类历史包袱不建议在生产代码中依赖。

## 为什么说"提升"不准确

"提升"暗示代码被移动了，但实际上：

1. 代码位置不变，只是**绑定**在进入作用域时就存在了
2. 初始化时机与代码执行顺序相关，不是"移动到顶部"
3. 函数声明是"整体可用"，`var` 是"存在但为 undefined"，`let` 是"存在但不可访问"

理解这三层差异，才能解释 `typeof` 的行为：

```js
typeof undeclared   // 'undefined' —— 完全不存在，不报错
typeof declaredLet  // ReferenceError —— 存在但 TDZ
let declaredLet
```

## 面试常问的组合

```js
var a = 1
function outer() {
  console.log(a)  // undefined（内层 var a 提升）
  var a = 2
  console.log(a)  // 2
}
outer()
```

内层的 `var a` 会遮蔽外层的 a，且它在函数入口就创建了，所以第一次输出 undefined。

::: interview 面试视角
"提升就是变量声明被移到顶部"是错误描述。正确说法是"绑定在执行上下文创建时建立"，并区分创建与初始化两个阶段。
:::
