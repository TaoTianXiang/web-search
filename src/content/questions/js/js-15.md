## 对照表

| | Map | Set | WeakMap | WeakSet |
| --- | --- | --- | --- | --- |
| 存储形式 | 键值对 | 值集合 | 键值对 | 对象集合 |
| 键类型 | 任意 | — | 仅对象 | 仅对象 |
| 可遍历 | ✅ | ✅ | ❌ | ❌ |
| 可获取 size | ✅ | ✅ | ❌ | ❌ |
| 引用强度 | 强 | 强 | 弱 | 弱 |
| 用途 | 字典、缓存 | 去重、集合运算 | 附加元数据 | 标记对象 |

## Map 相比普通对象

```js
const m = new Map()
m.set('a', 1)
m.set({}, 2)      // 对象也能做键
m.set(NaN, 3)     // NaN 作为键是相等的
m.size            // 3
```

优势：

1. 键可以是任意类型，且按引用 / SameValueZero 比较
2. 保证插入顺序
3. `size` 属性 O(1)
4. 频繁增删性能更好（对象删除属性会破坏隐藏类）

普通对象的问题：

```js
const obj = {}
obj.__proto__ = 'x'      // 原型污染
obj[{}] = 1              // 键被转成 '[object Object]'
'toString' in obj        // true，来自原型链
```

需要字典语义时用 `Object.create(null)` 或 `Map`。

## WeakMap 的弱引用

```js
let key = { id: 1 }
const wm = new WeakMap()
wm.set(key, { meta: 'data' })

key = null
// 下一轮 GC 后，这条记录会被自动清除，不会泄漏
```

三条限制都源于"弱引用"：

- **不能遍历**：不知道哪些键还活着，无法安全枚举
- **不能取 size**：同样原因
- **键必须是对象**：原始值无法建立弱引用

## 典型场景

```js
// 1. 给 DOM 节点附加数据（节点移除后自动回收）
const nodeData = new WeakMap()
nodeData.set(el, { clicks: 0 })

// 2. 对象缓存，避免内存泄漏
const cache = new WeakMap()
function getExpensive(obj) {
  if (!cache.has(obj)) cache.set(obj, compute(obj))
  return cache.get(obj)
}

// 3. 私有属性（class fields 之前的标准做法）
const priv = new WeakMap()
class Counter {
  constructor() { priv.set(this, { count: 0 }) }
  inc() { priv.get(this).count++ }
}

// 4. WeakSet 标记"已处理"
const seen = new WeakSet()
function walk(node) {
  if (seen.has(node)) return
  seen.add(node)
  // ...
}
```

## Set 的集合运算

```js
const a = new Set([1, 2, 3])
const b = new Set([2, 3, 4])

new Set([...a].filter((x) => b.has(x)))            // 交集
new Set([...a, ...b])                              // 并集
new Set([...a].filter((x) => !b.has(x)))           // 差集

// ES2025 原生方法（新浏览器）
a.union(b); a.intersection(b); a.difference(b)
```

## 性能对比

| 操作 | Map | 普通对象 |
| --- | --- | --- |
| 增删频繁 | 快 | 慢（形状变化） |
| 大量读取 | 相近 | 相近 |
| 序列化 | 需手动转 | `JSON.stringify` 直接可用 |

::: interview 面试视角
"WeakMap 不能遍历"这个答案本身没有价值，价值在于说明**为什么**：无法知道哪些键还存活。再补上"对象删除属性会破坏隐藏类"的性能背景，回答就有深度。
:::
