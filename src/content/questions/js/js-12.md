## 基础判断

```js
function isReference(v) {
  return (typeof v === 'object' && v !== null) || typeof v === 'function'
}
```

两个必须条件：

1. `typeof v === 'object'` 覆盖对象、数组、Date、Map 等，但 **`typeof null === 'object'`**，必须排除 null
2. `typeof v === 'function'` 单独判断，因为函数虽属于对象，但 typeof 返回 `'function'`

## typeof 的完整结果

| 值 | typeof |
| --- | --- |
| `undefined` | `'undefined'` |
| `null` | `'object'` ← 历史 bug |
| `true` | `'boolean'` |
| `1` / `NaN` | `'number'` |
| `1n` | `'bigint'` |
| `'a'` | `'string'` |
| `Symbol()` | `'symbol'` |
| `() => {}` | `'function'` |
| `[]` / `{}` / `new Map()` | `'object'` |

## 精确类型判断

```js
const typeOf = (v) => Object.prototype.toString.call(v).slice(8, -1)

typeOf([])          // 'Array'
typeOf(null)        // 'Null'
typeOf(new Map())   // 'Map'
typeOf(new Date())  // 'Date'
typeOf(/a/)         // 'RegExp'
typeOf(function(){}) // 'Function'
typeOf(1n)          // 'BigInt'
```

为什么不能直接 `v.toString()`：很多对象重写了 `toString`（如数组、Date），结果不可靠。必须借用 `Object.prototype.toString`。

## 判断纯对象

```js
function isPlainObject(v) {
  if (Object.prototype.toString.call(v) !== '[object Object]') return false
  const proto = Object.getPrototypeOf(v)
  return proto === null || proto === Object.prototype
}
```

```js
isPlainObject({})                    // true
isPlainObject(Object.create(null))   // true
isPlainObject(new class {})          // false
isPlainObject([])                    // false
```

## 判断数组

```js
Array.isArray([])  // ✅ 跨 iframe 可靠
[] instanceof Array // ❌ 跨 iframe 会失败（原型链不同）
```

跨 iframe / 跨 Realm 的场景，所有基于 `instanceof` 的判断都不可靠，因为每个窗口有独立的原型对象。此时只能靠 `toString` 或品牌检测方法（如 `Array.isArray`）。

## 判断类实例

```js
obj instanceof MyClass           // 单 Realm 内可靠
Object.getPrototypeOf(obj) === MyClass.prototype // 更严格
```

::: warn 常见陷阱
`typeof new String('a')` 是 `'object'`，而 `typeof 'a'` 是 `'string'`。包装对象会破坏所有基于 typeof 的判断。
:::

::: interview 面试视角
能说出"null 的 typeof 是 object 是历史 bug"以及"instanceof 跨 iframe 失效"，说明你处理过真实的边界问题。
:::
