## 核心思想：可达性

JavaScript 使用**标记-清除**（mark-and-sweep）：从根对象（全局对象、当前执行栈、闭包引用等）出发遍历，标记所有可达对象，未标记的即可回收。

引用计数已被淘汰，因为它无法处理循环引用：

```js
let a = {}
let b = {}
a.next = b
b.next = a
a = b = null // 引用计数不为 0 但已不可达，标记清除能回收
```

## V8 的分代回收

```
┌─────────────── 新生代 (New Space) ───────────────┐
│  From Space  │  To Space   ← Scavenge 复制算法    │
└──────────────────────────────────────────────────┘
            │ 晋升（存活两轮）
            ▼
┌─────────────── 老生代 (Old Space) ───────────────┐
│  Mark-Sweep  │  Mark-Compact  │  增量标记        │
└──────────────────────────────────────────────────┘
```

| 区域 | 算法 | 特点 |
| --- | --- | --- |
| 新生代 | Scavenge（复制） | 空间小、回收频繁、速度快 |
| 老生代 | 标记-清除 + 标记-整理 | 空间大、回收慢、用增量/并发减少停顿 |

**晋升条件**：对象在 Scavenge 中存活过两轮（或 To Space 使用超过 25%）。

大对象（如长字符串）直接分配到老生代，避免复制成本。

## 为什么需要增量标记

老生代全量标记可能停顿上百毫秒，造成掉帧。V8 用：

- **增量标记**：把标记拆成小片，与 JS 执行交替
- **并发标记 / 并发清理**：在辅助线程进行
- **惰性清理**：延迟回收，按需进行

## 前端常见泄漏

```js
// 1. 全局变量意外创建
function f() { leaked = 'x' }   // 没有声明，挂到 window

// 2. 定时器 / 监听未清理
setInterval(() => render(bigData), 1000)
window.addEventListener('resize', onResize)

// 3. 闭包持有大对象
const cache = new Map()   // 只增不减

// 4. Detached DOM：节点已移除但仍被引用
const nodes = []
document.body.removeChild(el)
nodes.push(el)            // el 无法回收

// 5. 订阅未取消
store.subscribe(handler)  // 组件卸载后仍被 store 引用
```

## 排查流程

1. **Performance 面板**：勾选 Memory，观察 JS Heap 曲线是否呈锯齿（正常）还是单调上升（泄漏）
2. **堆快照对比**：拍三次（操作前 / 反复操作后 / 再操作一次），对比同类对象数量
3. **Retainers 面板**：从可疑对象沿引用链向上找到持有者
4. **Detached 元素**：在快照中搜索 `Detached` 定位游离 DOM

```js
// 也可以主动观测
const registry = new FinalizationRegistry((id) => console.log('collected', id))
registry.register(obj, 'obj-1')
```

## 弱引用与缓存设计

| API | 用途 |
| --- | --- |
| `WeakMap` / `WeakSet` | 附加元数据、标记 |
| `WeakRef` | 持有弱引用（需配合清理逻辑） |
| `FinalizationRegistry` | 回收后的回调（不可依赖时机） |

::: warn 不要依赖 GC 时机
`WeakRef.deref()` 返回 undefined 只能说明"已被回收"，不能说明"何时被回收"。业务逻辑不应依赖 GC 时机。
:::

::: interview 面试视角
能从"可达性"讲到"分代 + 增量标记"，再落到"Detached DOM 与订阅泄漏的排查流程"，就是完整链路。只背"标记清除"是入门水平。
:::
