## 完整实现

```js
class EventEmitter {
  constructor() {
    this.events = new Map() // 事件名 → Set<{ fn, once }>
  }

  on(name, fn) {
    if (!this.events.has(name)) this.events.set(name, new Set())
    const entry = { fn, once: false }
    this.events.get(name).add(entry)

    // 返回取消函数：调用方无需保存 name/fn，避免解绑写错
    return () => this.off(name, fn)
  }

  once(name, fn) {
    if (!this.events.has(name)) this.events.set(name, new Set())
    this.events.get(name).add({ fn, once: true })
    return () => this.off(name, fn)
  }

  off(name, fn) {
    const set = this.events.get(name)
    if (!set) return
    if (!fn) {
      this.events.delete(name) // 不传 fn 则清空该事件
      return
    }
    for (const entry of set) {
      if (entry.fn === fn) {
        set.delete(entry)
        break
      }
    }
    if (set.size === 0) this.events.delete(name)
  }

  emit(name, ...args) {
    const set = this.events.get(name)
    if (!set) return false

    // 复制一份，避免回调内部 off/on 时修改正在遍历的集合
    for (const entry of [...set]) {
      try {
        entry.fn.apply(this, args)
      } catch (err) {
        // 异常隔离：一个订阅者报错不应阻断其他订阅者
        console.error(err)
      }
      if (entry.once) set.delete(entry)
    }
    return true
  }

  listenerCount(name) {
    return this.events.get(name)?.size ?? 0
  }
}
```

## 五个必须处理的细节

| 细节 | 原因 |
| --- | --- |
| `emit` 遍历副本 | 回调中调用 `off` 会修改集合，直接遍历会漏掉或报错 |
| `once` 执行后移除 | 必须在**执行后**移除，执行中移除会让回调里再 emit 时重复触发 |
| 异常隔离 | 一个订阅者抛错不能影响其他订阅者 |
| `off` 清理空集合 | 否则 Map 会无限增长（内存泄漏） |
| 返回取消函数 | 调用方不必保存 `name/fn`，减少解绑失误 |

## 为什么用 Map + Set

```js
// 用对象的问题
const handlers = { click: [fn] }
handlers['__proto__'] = ... // 原型污染风险
handlers['constructor']      // 与非事件名冲突

// Set 保证同一个 fn 不会重复注册（除非业务需要）
```

## 真实使用场景

```js
// 1. 跨组件通信（无需引入状态管理）
const bus = new EventEmitter()
bus.on('user:logout', () => router.push('/login'))

// 2. 插件系统
plugin.on('beforeRender', (ctx) => { /* ... */ })

// 3. Node 的 events 模块就是这个模型的实现
import { EventEmitter } from 'node:events'
```

## 与观察者模式的区别

| | 发布订阅 | 观察者 |
| --- | --- | --- |
| 耦合 | 通过事件中心解耦 | 主体直接持有观察者列表 |
| 依赖方向 | 发布者与订阅者互不知道 | 观察者依赖主体 |

EventEmitter 是发布订阅的典型实现。
