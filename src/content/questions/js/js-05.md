## 三条关系

```js
function Foo() {}
const f = new Foo()

Foo.prototype        // 函数自带的对象，供实例共享
f.__proto__          // === Foo.prototype
Foo.__proto__        // === Function.prototype
```

```
f ──[[Prototype]]──> Foo.prototype ──> Object.prototype ──> null
                            ▲
                            │ constructor
                           Foo
Foo ──[[Prototype]]──> Function.prototype ──> Object.prototype ──> null
```

| 属性 | 归属 | 含义 |
| --- | --- | --- |
| `prototype` | 只有函数有 | 用 new 创建实例时的原型对象 |
| `__proto__`（`[[Prototype]]`） | 所有对象都有 | 当前对象的原型引用 |

## instanceof 的判定逻辑

`A instanceof B` 的规范行为是：**沿 A 的原型链向上查找，看是否存在某个原型对象等于 `B.prototype`**。

```js
function myInstanceof(obj, Ctor) {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) return false
  const target = Ctor.prototype
  let proto = Object.getPrototypeOf(obj)
  while (proto) {
    if (proto === target) return true
    proto = Object.getPrototypeOf(proto)
  }
  return false
}
```

注意两个边界：

```js
Object.create(null) instanceof Object   // false —— 没有原型链
1 instanceof Number                     // false —— 原始值不参与
new Number(1) instanceof Number         // true
```

## 为什么 typeof 不够

```js
typeof []        // 'object'
typeof null      // 'object'（历史 bug）
typeof new Map() // 'object'
```

更可靠的类型检测：

```js
const typeOf = (v) => Object.prototype.toString.call(v).slice(8, -1)
typeOf([])        // 'Array'
typeOf(null)      // 'Null'
typeOf(new Map()) // 'Map'
Array.isArray([]) // true
```

## 属性查找的性能含义

属性访问会沿原型链向上找，链越长越慢。把方法放在原型上而不是每个实例各存一份，可以显著节省内存：

```js
// 差：每个实例一份函数
function A() { this.fn = function () {} }

// 好：共享一份
function B() {}
B.prototype.fn = function () {}
```

现代引擎用**隐藏类（hidden class）+ 内联缓存**优化属性访问，前提是对象形状稳定。动态增删属性会破坏形状，反而更慢：

```js
class Point {
  constructor(x, y) {
    this.x = x
    this.y = y   // 一次性定义全部字段，形状稳定
  }
}
```

::: warn 不要用 __proto__ 写业务代码
它是历史遗留访问器，性能差且可被覆盖。使用 `Object.getPrototypeOf` / `Object.setPrototypeOf` / `Object.create`。
:::

::: interview 面试视角
手写 instanceof 时要说明"原始值返回 false"和"原型链终止于 null"这两个边界，否则实现会在 `Object.create(null)` 与原始值上出错。
:::
