## 原因：二进制无法精确表示十进制小数

```js
0.1 + 0.2                    // 0.30000000000000004
0.1 + 0.7                    // 0.7999999999999999
1.005 * 100                  // 100.49999999999999
```

IEEE 754 双精度用 1 位符号 + 11 位指数 + 52 位尾数表示，本质是二进制分数。`0.1` 在二进制中是无限循环小数，存储时被截断，必然产生误差。

```js
(0.1).toString(2) // '0.0001100110011001100110011001100110011001100110011001101'
```

误差会随运算累积，所以 `0.1 + 0.2` 的结果是 `0.30000000000000004`。

## 安全整数范围

```js
Number.MAX_SAFE_INTEGER  // 9007199254740991
9007199254740993          // 实际是 9007199254740992（已丢精度）
```

超过 2^53 - 1 后整数运算也不可靠，需改用 `bigint`。

## 解决方案

### 1. 转整数运算（金额首选）

```js
// 以"分"为单位
const a = 10  // 0.10 元
const b = 20  // 0.20 元
const sum = (a + b) / 100 // 0.3

// 或乘系数后取整
const calc = (x, y) => Math.round(x * 100 + y * 100) / 100
```

### 2. 容差比较

```js
const isEqual = (a, b, eps = Number.EPSILON) => Math.abs(a - b) < eps

// 注意：Number.EPSILON 只适合接近 1 的量级
// 更大数值时应按量级放大容差
const nearlyEqual = (a, b) => Math.abs(a - b) <= Number.EPSILON * Math.max(Math.abs(a), Math.abs(b))
```

`Number.EPSILON` 是 1 与大于 1 的最小浮点数之差，约 `2.22e-16`。

### 3. 定点小数库

```js
import Decimal from 'decimal.js'
new Decimal('0.1').plus('0.2').equals('0.3') // true
```

或 `big.js`、`bignumber.js`。金融场景必须用这类库，或直接用整数分。

### 4. toFixed 的陷阱

```js
(1.005).toFixed(2)  // '1.00'，不是 '1.01'
(1.45).toFixed(1)   // '1.4'，不是 '1.5'
```

因为 `1.005` 实际存储为 `1.00499999...`，四舍五入后向下。正确做法：

```js
function round(num, digits) {
  const factor = 10 ** digits
  return Math.round((num + Number.EPSILON) * factor) / factor
}
```

## 其他表现

```js
0.1 * 3            // 0.30000000000000004
0.3 / 0.1          // 2.9999999999999996
Math.pow(0.1, 2)   // 0.010000000000000002

// 位运算只适用于 32 位整数
1 << 30  // 1073741824
1 << 31  // -2147483648（溢出为负数）
```
