## 结果

```js
['1', '2', '3'].map(parseInt)
// [1, NaN, NaN]
```

## 原因：回调参数错位

`map` 会向回调传三个参数：`(item, index, array)`。`parseInt` 的签名是 `(string, radix)`。所以实际调用变成：

```js
parseInt('1', 0, arr)  // radix=0 → 按 10 进制 → 1
parseInt('2', 1, arr)  // radix=1 → 非法进制 → NaN
parseInt('3', 2, arr)  // radix=2 → '3' 不是二进制字符 → NaN
```

关键点：`parseInt` 的第二个参数是**进制**，被 map 的 index 占用了。

`radix` 的合法范围是 2–36。0 被视为 10（除非字符串以 `0x` 开头）。

## 正确写法

```js
// 1. 一元 +（最简洁，只接受十进制）
['1', '2', '3'].map(Number)      // [1, 2, 3]
['1', '2', '3'].map((v) => +v)   // [1, 2, 3]

// 2. 显式传 radix
['1', '2', '3'].map((v) => parseInt(v, 10)) // [1, 2, 3]

// 3. 避免 parseInt 的隐式行为
['08', '09'].map(Number)                 // [8, 9]
['08', '09'].map((v) => parseInt(v, 10)) // [8, 9]
```

## parseInt 与 Number 的差异

| 输入 | `parseInt` | `Number` |
| --- | --- | --- |
| `'12px'` | 12 | NaN |
| `''` | NaN | 0 |
| `' 12 '` | 12 | 12 |
| `'0x10'` | 16 | 16 |
| `'1e3'` | 1 | 1000 |
| `'12.7'` | 12 | 12.7 |

`parseInt` 是"逐字符解析直到非法"，`Number` 是"整体转换"。做严格数值校验时用 `Number` + 检查。

## 同类陷阱

```js
['1','2','3'].map(parseFloat)  // [1, 2, 3] —— parseFloat 只接收一个参数，安全
['1','2','3'].map(isNaN)       // [false, false, false] —— isNaN 只接收一个参数
['1','2','3'].filter(Boolean)  // ['1','2','3']

// 但下面会出问题：
['1','2','3'].map(parseInt.bind(null))  // [1, 2, 3] —— 绑定了 null 作为 this，radix 仍是 index
```

::: warn 面试官想听到什么
不是"答案是 [1, NaN, NaN]"，而是"因为 map 传了 index 作为 parseInt 的 radix"。能主动指出 radix 合法范围 2–36，并给出三种正确写法，才是完整回答。
:::
