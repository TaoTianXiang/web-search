## Set（最简洁）

```js
const unique = [...new Set(arr)]

// Set 用 SameValueZero 比较，NaN 被视为相等
[...new Set([NaN, NaN, 1])] // [NaN, 1]
```

局限：对象按引用比较，`{a:1}` 与 `{a:1}` 被认为不同。

## 手写哈希去重（保留首次出现顺序）

```js
function unique(arr) {
  const seen = new Set()
  const out = []
  for (const item of arr) {
    if (seen.has(item)) continue
    seen.add(item)
    out.push(item)
  }
  return out
}
```

时间 O(n)，空间 O(n)，是实践中的最优解。

## 其他写法及问题

```js
// 1. filter + indexOf：O(n²)
arr.filter((v, i) => arr.indexOf(v) === i)

// 2. reduce + includes：O(n²)
arr.reduce((acc, v) => (acc.includes(v) ? acc : [...acc, v]), [])

// 3. 对象当字典：键会被转成字符串
const seen = {}
arr.filter((v) => {
  if (seen[v]) return false
  seen[v] = true
  return true
})
// [1, '1'] 会被误判为重复；'__proto__' 会有原型污染问题
```

## 特殊值的处理

| 值 | Set | indexOf |
| --- | --- | --- |
| `NaN` | 相等 | 不等（`indexOf` 用 ===） |
| `0` / `-0` | 相等 | 相等 |
| 对象字面量 | 引用不同即不同 | 同 |
| Symbol | 引用不同即不同 | 同 |

所以 `[NaN, NaN].filter((v,i)=>arr.indexOf(v)===i)` 会保留两个 NaN，而 Set 版本只保留一个。

## 按字段去重

```js
function uniqueBy(list, keyFn) {
  const seen = new Set()
  return list.filter((item) => {
    const key = typeof keyFn === 'function' ? keyFn(item) : item[keyFn]
    if (seen.has(key)) return false
    seen.add(key)
    return true
  })
}

uniqueBy(users, 'id')
uniqueBy(users, (u) => `${u.orgId}:${u.role}`)
```

## 大数组的取舍

| 方法 | 时间 | 适用 |
| --- | --- | --- |
| Set | O(n) | 通用首选 |
| filter + indexOf | O(n²) | 小数组、代码简洁 |
| 对象字典 | O(n) | 仅当值都是字符串且无原型污染风险 |
| sort + 相邻比较 | O(n log n) | 需要排序结果时顺手去重 |

::: warn 不要用 JSON.stringify 做对象去重
键顺序不同会导致同一对象被判定为不同，且循环引用会直接抛错。
:::

能指出"indexOf 对 NaN 失效"与"对象当字典会把键转字符串"，说明你真的测过边界而不是只背 Set。
:::
