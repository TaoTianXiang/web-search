## 三条指向

```js
function Foo() {}
const f = new Foo()

Foo.prototype              // Foo 的原型对象
Foo.prototype.constructor  // Foo 本身
f.__proto__                // Foo.prototype
f.constructor              // Foo（沿原型链找到）
```

所以"构造函数的 prototype 指向一个对象，该对象的 constructor 指回构造函数"，这是默认的循环关系。

## 默认 prototype 的结构

```js
Object.getOwnPropertyDescriptor(Foo, 'prototype')
// { value: { constructor: Foo }, writable: true, enumerable: false, configurable: false }
```

注意：`prototype` 本身**不可枚举、不可配置、可写**。所以 `for...in` 遍历函数时看不到它。

## 整体替换 prototype 的后果

```js
function Foo() {}
Foo.prototype = { say() {} }

const f = new Foo()
f.constructor === Foo      // false！constructor 丢失
f.constructor === Object   // true，沿链找到 Object
```

修复方式：

```js
Foo.prototype = { say() {} }
Object.defineProperty(Foo.prototype, 'constructor', {
  value: Foo,
  enumerable: false,
  writable: true,
  configurable: true
})
```

## 为什么 constructor 不可靠

实例的 `constructor` 只是**沿原型链查找到的一个普通属性**，不是语言层面的真值。它可以被任意覆盖：

```js
const obj = { constructor: 'hacked' }
```

所以判断类型时不要用 `obj.constructor === X`，用 `instanceof` 或 `toString`。

## class 的差异

```js
class A { method() {} }
Object.getOwnPropertyDescriptor(A.prototype, 'method').enumerable // false
A.prototype.constructor === A // true
```

class 的方法**不可枚举**，而构造函数里手工挂的方法默认可枚举。这是遍历原型属性时容易忽略的差异。

## 与 Object.create 的关系

```js
// 等价于 new Foo() 的原型部分
const obj = Object.create(Foo.prototype)
```

`Object.create(proto)` 直接指定原型，不调用构造函数，也不初始化实例属性。这是寄生组合继承的基础。
