## 会改变原数组（mutating）

| 方法 | 作用 | 备注 |
| --- | --- | --- |
| `push` / `pop` | 尾部增删 | 返回长度 / 被删元素 |
| `unshift` / `shift` | 头部增删 | O(n)，大数据量慎用 |
| `splice` | 任意位置增删 | 返回被删元素数组 |
| `sort` | 排序 | 默认按字符串比较，**原地排序** |
| `reverse` | 反转 | 原地 |
| `fill` | 填充 | 原地 |
| `copyWithin` | 内部复制 | 原地 |

```js
const a = [3, 1, 10]
a.sort()          // [1, 10, 3] —— 默认按字符串比较的坑
a.sort((x, y) => x - y) // [1, 3, 10]

const b = [1, 2, 3]
b.sort()          // 返回同一个数组引用
```

## 不会改变原数组（non-mutating）

```js
map / filter / reduce / reduceRight
flat / flatMap / concat / slice
join / indexOf / lastIndexOf / includes / find / findIndex
some / every / keys / values / entries
toSorted / toReversed / toSpliced / with   // ES2023 新增的不可变版本
```

```js
// ES2023：不可变版本的原地方法
const arr = [3, 1, 2]
const sorted = arr.toSorted((a, b) => a - b) // 原数组不变
const reversed = arr.toReversed()
const spliced = arr.toSpliced(0, 1)          // 删除索引 0 的 1 个
const replaced = arr.with(1, 99)             // 替换索引 1
```

## 在 React 中的影响

React 依赖**引用相等**判断是否需要重新渲染，原地修改会导致状态"看起来没变"：

```js
// ❌ 原地排序，引用不变，React 可能不重渲染
setList(list.sort(cmp))

// ✅ 先复制
setList([...list].sort(cmp))
setList(list.toSorted(cmp))
```

## 在 Vue 3 中的影响

Vue 3 用 Proxy 能拦截索引赋值，所以 `list[0] = x` 也能触发更新。但**整体替换**与**原地修改**在可预测性上仍有差异：

```js
// Vue 3 可用，但不是好的实践
state.list.push(item)

// 更清晰：明确表达意图
state.list = [...state.list, item]
```

## 性能提示

`shift` / `unshift` 是 O(n)（需要移动后续元素）。大列表应改用队列索引或 `push` + 反向遍历。

```js
// 用索引模拟队列，避免 O(n)
let head = 0
const queue = []
queue.push(1)
const item = queue[head++]  // O(1)
```
