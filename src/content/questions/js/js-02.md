## 对照表

| 维度 | var | let | const |
| --- | --- | --- | --- |
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 绑定创建 | 进入作用域立即创建 | 同左 | 同左 |
| 初始化 | 立即初始化为 `undefined` | 执行到声明语句 | 执行到声明语句 |
| TDZ | 无 | 有 | 有 |
| 重复声明 | 允许 | 报错 | 报错 |
| 挂到全局对象 | 浏览器中 `var` 会 | 不会 | 不会 |

## "提升"到底是什么

规范里没有"提升"这个词。真实机制是：**进入作用域时先创建绑定（Binding）**，然后在特定时机初始化。

```js
console.log(a) // undefined —— 已创建且已初始化为 undefined
var a = 1

console.log(b) // ReferenceError —— 已创建但未初始化，处于 TDZ
let b = 2
```

所以"let 没有提升"是错误说法。准确描述是：**let 提升了绑定，但直到声明语句执行前都处于未初始化状态，访问会抛错。**

`typeof` 也一样会抛错，这可以用来区分：

```js
typeof undeclaredVar // 'undefined'（不存在，不报错）
typeof tdzVar        // ReferenceError（存在但未初始化）
let tdzVar
```

## TDZ 的边界

TDZ 覆盖**整个块**，而不只是声明之前：

```js
{
  // 从这里开始 tdz 就生效
  console.log(x) // ReferenceError
  let x = 1
}
```

函数参数默认值中也有 TDZ：

```js
function f(a = b, b = 1) {} // 调用 f() 时 a 求值，b 还在 TDZ → ReferenceError
```

## 循环中的 let

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)) // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)) // 0 1 2
```

规范为 `for` 的 let 绑定做了特殊处理：每轮迭代创建新的词法环境，并把上一轮的值拷贝过去，因此三个回调捕获的是独立变量。Babel 降级时用闭包函数模拟：

```js
for (var _i = 0; _i < 3; _i++) {
  (function (i) { setTimeout(() => console.log(i)) })(_i)
}
```

## const 的真实约束

`const` 只保证**绑定不可重新赋值**：

```js
const obj = { a: 1 }
obj.a = 2        // ✅ 允许
obj = {}         // ❌ TypeError

const arr = []
arr.push(1)      // ✅ 允许
```

需要不可变语义时必须配合 `Object.freeze`（浅冻结）或结构化不可变方案。

::: warn 常见坑
`for (const i = 0; i < 3; i++)` 会在第二轮 `i++` 时报错 —— const 绑定不能重新赋值。循环变量用 let 而不是 const。
:::

::: interview 面试视角
能说清"提升的是绑定而非初始化"这一层，就跳出了背概念的层次。再补上 `for` 的每轮绑定规则，基本可以判断为高分回答。
:::
