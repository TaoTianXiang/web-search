## 判定流程（IsLooselyEqual）

1. 类型相同 → 走 `===`
2. `null == undefined` → true（且仅此一对）
3. number 与 string → string 转 number
4. boolean 与任意 → boolean 先转 number
5. object 与原始值 → object 走 ToPrimitive
6. 其余 → false

## ToPrimitive

| hint | 顺序 |
| --- | --- |
| number（默认） | `Symbol.toPrimitive` → `valueOf` → `toString` |
| string | `Symbol.toPrimitive` → `toString` → `valueOf` |
| default | 除 Date 外按 number 处理 |

```js
const obj = {
  valueOf() { return 42 },
  toString() { return 'str' }
}
obj + 1        // 43（default → valueOf）
`${obj}`      // 'str'（string hint → toString）
String(obj)    // 'str'
Number(obj)    // 42
```

## 经典题拆解

```js
[] == ![]
```

1. `![]` → `false`（[] 是真值）
2. `false` 是 boolean → 转 number `0`
3. 左侧 `[]` 是对象 → ToPrimitive → `''` → 转 number `0`
4. `0 == 0` → **true**

其余常见结论：

```js
null == 0        // false —— 特例，不进入数值转换
null >= 0        // true  —— 关系运算符走 ToNumber
'0' == false     // true
[0] == false     // true
[1] == true      // true
({}) == '[object Object]' // true
```

## 为什么工程里禁 ==

除了 `x == null` 这一种（同时覆盖 null 与 undefined）的合理用法外，隐式转换没有可预测收益：

```js
if (value == null) {} // 允许：同时排除 null 和 undefined
if (value === 0) {}   // 其余一律用 ===
```

ESLint 可用 `eqeqeq: ['error', 'smart']` 只允许这一种。

## Object.is 修的两个洞

```js
NaN === NaN        // false
0 === -0           // true

Object.is(NaN, NaN) // true
Object.is(0, -0)    // false
```

React 的依赖比较、Vue 的 `hasChanged` 都用 `Object.is`，正是为了正确处理这两类值。
