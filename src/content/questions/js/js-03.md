## 一句话定义

闭包 = **函数 + 其定义时的词法环境**。当内部函数引用了外部作用域的变量，且内部函数存活，该变量就不会被回收。

## 保留粒度：变量级而非作用域级

V8 会做上下文分配优化：只有被内部函数**实际引用**的变量才进入堆上的 `Context` 对象。

```js
function make() {
  const huge = new Array(1e6).fill(0) // 未被引用 → 随栈帧释放
  const small = 1
  return () => small
}
```

但以下情况会让优化退化（整个作用域被保留）：

- 使用 `eval` 或 `with`（无法静态分析）
- 变量的访问方式是动态计算的

## 三个真实场景

### 1. 私有状态与模块封装

```js
function createStore(initial) {
  let state = initial
  const listeners = new Set()
  return {
    get: () => state,
    set(next) {
      state = next
      listeners.forEach((fn) => fn(state))
    },
    subscribe(fn) {
      listeners.add(fn)
      return () => listeners.delete(fn) // 取消订阅的闭包
    }
  }
}
```

### 2. 函数工厂 / 参数固化

```js
const logger = (scope) => (level, msg) => console.log(`[${scope}][${level}] ${msg}`)
const apiLog = logger('api')
apiLog('error', 'timeout')
```

### 3. 缓存与惰性求值

```js
function memo(fn) {
  const cache = new Map()
  return (key) => {
    if (!cache.has(key)) cache.set(key, fn(key))
    return cache.get(key)
  }
}
```

## 泄漏的真实形态

| 场景 | 代码 |
| --- | --- |
| 定时器持有大对象 | `setInterval(() => render(hugeData), 1000)` 未清理 |
| 事件监听未解绑 | `window.addEventListener('resize', onResize)` 无 remove |
| 全局缓存无上限 | `const cache = new Map()` 只增不减 |
| 订阅未释放 | 组件卸载后仍然被 store 的 listeners 引用 |

```js
// 正确写法：成对清理
useEffect(() => {
  const id = setInterval(tick, 1000)
  window.addEventListener('resize', onResize)
  return () => {
    clearInterval(id)
    window.removeEventListener('resize', onResize)
  }
}, [])
```

## 排查方法

1. Chrome DevTools → **Memory** → 拍三次堆快照（操作前 / 反复操作后 / 再操作一次）
2. 对比快照，看某类对象的实例数是否单调增长
3. 选中可疑对象 → **Retainers** 面板 → 沿引用链找到持有者（通常是某个 `Context` 或事件监听）
4. 用 `Detached DOM` 过滤，定位"已从文档移除但仍被引用"的节点

```js
// 也可以主动用 WeakRef / FinalizationRegistry 观测
const ref = new WeakRef(bigObject)
// 稍后 ref.deref() 若为 undefined，说明已被回收
```

::: tip WeakMap 为什么能避免泄漏
`WeakMap` 的键是弱引用：只要键对象没有被其他地方引用，条目会被自动清除。适合"给对象附加元数据"的场景，如缓存 DOM 节点的计算结果。
:::
