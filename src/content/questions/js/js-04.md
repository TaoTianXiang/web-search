## 语义区别

| | 防抖 debounce | 节流 throttle |
| --- | --- | --- |
| 触发时机 | 停止触发后 wait 毫秒执行一次 | 每 wait 毫秒最多执行一次 |
| 典型场景 | 搜索输入、窗口 resize 结束后计算、表单校验 | 滚动监听、拖拽、鼠标移动、埋点上报 |
| 高频下的行为 | 一直不执行，直到停下来 | 匀速执行，保证有反馈 |

## 防抖实现

```js
function debounce(fn, wait = 300, immediate = false) {
  let timer = null
  let lastArgs = null
  let lastThis = null

  function invoke() {
    timer = null
    if (!immediate && lastArgs) {
      fn.apply(lastThis, lastArgs)
      lastArgs = lastThis = null
    }
  }

  function debounced(...args) {
    const callNow = immediate && !timer
    if (timer) clearTimeout(timer)
    lastArgs = args
    lastThis = this
    timer = setTimeout(invoke, wait)
    if (callNow) {
      fn.apply(this, args)
      lastArgs = lastThis = null
    }
  }

  debounced.cancel = () => {
    if (timer) clearTimeout(timer)
    timer = null
    lastArgs = lastThis = null
  }

  return debounced
}
```

三个必须处理的细节：

1. **this 与参数**：通过 `lastThis/lastArgs` 保存最后一次调用的上下文
2. **immediate**：首次立即执行，之后需等待停止触发
3. **cancel**：组件卸载时必须能取消挂起调用，否则会在已销毁的组件上执行

## 节流实现（含 leading / trailing）

```js
function throttle(fn, wait = 300, { leading = true, trailing = true } = {}) {
  let timer = null
  let lastTime = 0
  let lastArgs = null
  let lastThis = null

  function invoke(time) {
    lastTime = leading === false ? 0 : time
    timer = null
    if (lastArgs) {
      fn.apply(lastThis, lastArgs)
      lastArgs = lastThis = null
    }
  }

  function throttled(...args) {
    const now = Date.now()
    if (!lastTime && leading === false) lastTime = now

    const remaining = wait - (now - lastTime)
    lastArgs = args
    lastThis = this

    if (remaining <= 0 || remaining > wait) {
      if (timer) {
        clearTimeout(timer)
        timer = null
      }
      invoke(now)
    } else if (!timer && trailing) {
      timer = setTimeout(() => invoke(Date.now()), remaining)
    }
  }

  throttled.cancel = () => {
    if (timer) clearTimeout(timer)
    timer = null
    lastTime = 0
    lastArgs = lastThis = null
  }

  return throttled
}
```

为什么判断 `remaining > wait`：处理系统时间被回拨（`now < lastTime`）的情况，否则会长时间不执行。

## 直接使用 rAF 的变体

滚动与动画场景可用 `requestAnimationFrame` 替代，天然与帧对齐：

```js
function rafThrottle(fn) {
  let ticking = false
  return (...args) => {
    if (ticking) return
    ticking = true
    requestAnimationFrame(() => {
      fn(...args)
      ticking = false
    })
  }
}
```

::: warn 常见错误
`window.addEventListener('scroll', debounce(handler, 200))` 在 React 中每次渲染都会重新创建防抖函数，导致状态混乱。必须用 `useMemo` / `useRef` 固化，或用 `useCallback` + 稳定的依赖。
:::

::: interview 面试视角
面试官通常关心三点：this/参数是否正确透传、cancel 是否存在、leading/trailing 的边界（首次是否触发、末次是否补执行）。能主动提到"系统时间回拨"和 React 中的引用稳定性，会明显加分。
:::
