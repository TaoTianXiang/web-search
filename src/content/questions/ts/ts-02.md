## 映射类型基础语法

```ts
{ [K in keyof T]?: T[K] }
```

三个关键符号：

| 符号 | 作用 |
| --- | --- |
| `in` | 遍历键集合 |
| `?:` | 加可选修饰符 |
| `-?:` | **移除**可选修饰符 |
| `readonly` | 加只读 |
| `-readonly` | 移除只读 |
| `as` | 键重映射（4.1+） |

## 手写实现

```ts
// 1. Partial：全部变可选
type MyPartial<T> = { [K in keyof T]?: T[K] }

// 2. Required：全部变必填（-? 移除可选）
type MyRequired<T> = { [K in keyof T]-?: T[K] }

// 3. Readonly：全部只读
type MyReadonly<T> = { readonly [K in keyof T]: T[K] }

// 4. Pick：挑选子集
type MyPick<T, K extends keyof T> = { [P in K]: T[P] }

// 5. Omit：排除若干键
type MyOmit<T, K extends keyof any> = MyPick<T, Exclude<keyof T, K>>

// 6. Record
type MyRecord<K extends keyof any, V> = { [P in K]: V }
```

## 条件类型类

```ts
// 7. Exclude：从 T 中排除可赋给 U 的成员
type MyExclude<T, U> = T extends U ? never : T

// 8. Extract：保留可赋给 U 的成员
type MyExtract<T, U> = T extends U ? T : never

// 9. NonNullable
type MyNonNullable<T> = T extends null | undefined ? never : T

// 10. ReturnType（用 infer 推断）
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never

// 11. Parameters
type MyParameters<T> = T extends (...args: infer P) => any ? P : never

// 12. Awaited（递归展开 Promise）
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T
```

## 分布式条件类型

关键在于"裸类型参数"：

```ts
type MyExclude<'a' | 'b' | 'c', 'a'>
// 分布式展开为：
// ('a' extends 'a' ? never : 'a')
// | ('b' extends 'a' ? never : 'b')
// | ('c' extends 'a' ? never : 'c')
// = never | 'b' | 'c' = 'b' | 'c'
```

阻止分布用元组包裹：

```ts
type NoDistribute<T> = [T] extends [string] ? T : never
// string | number 作为整体判断，不拆开
```

## 键重映射（as）

```ts
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]
}

interface User { name: string; age: number }
type UserGetters = Getters<User>
// { getName: () => string; getAge: () => number }
```

`string & K` 是因为 `K` 可能是 `string | number | symbol`，而 `Capitalize` 只接受 string。

用 `as ... never` 可以过滤键：

```ts
// 只保留函数类型的键
type FunctionKeys<T> = {
  [K in keyof T as T[K] extends (...args: any) => any ? K : never]: T[K]
}
```

## Omit 在联合类型上的坑

```ts
type A = { a: 1; b: 2 }
type B = { a: 1; c: 3 }
type AB = A | B

type OmitA = Omit<AB, 'a'>
// 期望 { b: 2 } | { c: 3 }
// 实际 {} —— 因为 keyof (A|B) 只保留公共键
```

修复：手写分布式版本

```ts
type DistributiveOmit<T, K extends keyof any> = T extends any
  ? Omit<T, K>
  : never

type Fixed = DistributiveOmit<AB, 'a'>   // { b: 2 } | { c: 3 }
```

这是高级面试的常见追问点。

## 其他常用工具类型

| 类型 | 作用 |
| --- | --- |
| `Uppercase` / `Lowercase` / `Capitalize` / `Uncapitalize` | 字符串变换 |
| `ConstructorParameters` | 构造函数参数 |
| `InstanceType` | 实例类型 |
| `ThisParameterType` | this 参数类型 |
| `OmitThisParameter` | 去掉 this 参数 |

::: warn 不要滥用类型体操
深层嵌套的条件类型会：
1. 显著拖慢 tsc（大项目可能慢几秒）
2. 报错信息难以阅读（三层 never 嵌套）
3. 团队其他人无法维护

判断标准：这个类型是否阻止了**真实发生过的 bug**。
:::

::: interview 面试视角
手写 Omit 时主动指出"对联合类型不分发"这个坑，并给出 `DistributiveOmit` 的修复，是区分中级与高级的关键点。
:::
