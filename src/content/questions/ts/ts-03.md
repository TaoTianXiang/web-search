## 八种收窄手段

| 手段 | 示例 | 适用 |
| --- | --- | --- |
| `typeof` | `typeof x === 'string'` | 原始类型 |
| 真值判断 | `if (x)` | 排除 null / undefined / '' |
| `instanceof` | `e instanceof Error` | 类实例 |
| `in` | `'data' in res` | 区分对象形状 |
| 字面量比较 | `s.status === 'ok'` | 判别联合 |
| 相等性 | `x === null` | 精确判断 |
| 自定义守卫 | `isUser(x)` | 复杂结构 |
| 断言函数 | `assertUser(x)` | 校验后收窄 |

## 判别联合（最常用）

```ts
type Result =
  | { ok: true; data: User }
  | { ok: false; error: Error }

function handle(r: Result) {
  if (r.ok) {
    console.log(r.data.name)   // ✅ 收窄到成功分支
  } else {
    console.log(r.error.message) // ✅ 收窄到失败分支
  }
}
```

## 自定义类型守卫

```ts
interface User { id: string; name: string }

function isUser(v: unknown): v is User {
  return (
    typeof v === 'object' &&
    v !== null &&
    'id' in v &&
    typeof (v as User).id === 'string' &&
    'name' in v &&
    typeof (v as User).name === 'string'
  )
}

function handle(v: unknown) {
  if (isUser(v)) {
    console.log(v.name)   // ✅ 已收窄为 User
  }
}
```

返回类型 `v is User` 是关键：它告诉编译器"当返回 true 时，v 的类型是 User"。

## 断言函数（asserts）

```ts
function assertUser(v: unknown): asserts v is User {
  if (!isUser(v)) throw new TypeError('not a user')
}

function handle(v: unknown) {
  assertUser(v)
  console.log(v.name)   // ✅ 之后整个作用域都是 User
}
```

与守卫的区别：断言函数**不返回值**，靠抛错来保证后续代码的类型。

```ts
// 也可用于断言"非空"
function assertDefined<T>(v: T | null | undefined, msg?: string): asserts v is T {
  if (v == null) throw new Error(msg ?? 'value is nil')
}
```

## 穷尽性检查

```ts
type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'rect'; w: number; h: number }

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2
    case 'rect':   return s.w * s.h
    default:
      return assertNever(s)   // 新增分支时这里会编译报错
  }
}

function assertNever(x: never): never {
  throw new Error(`Unexpected: ${JSON.stringify(x)}`)
}
```

当联合新增 `{ kind: 'triangle' }` 时，`default` 里的 `s` 不再是 `never`，`assertNever` 立即报错。这是"把运行时遗漏变成编译期错误"的标准手法。

## 收窄的边界

### 1. 闭包中的收窄

```ts
function f(x: string | number) {
  if (typeof x === 'string') {
    setTimeout(() => {
      x.toUpperCase()   // ✅ 仍收窄（x 未被重新赋值）
    })
  }
}
```

但如果变量被重新赋值，收窄会失效：

```ts
function f(x: string | number) {
  if (typeof x === 'string') {
    x = 'other'    // 赋值后类型变宽
    // 后续不再收窄
  }
}
```

### 2. 回调中的收窄失效

```ts
let value: string | null = 'a'

if (value !== null) {
  // ✅ 此处已收窄
  someAsyncFn(() => {
    value.toUpperCase()   // ❌ 回调执行时可能已被置为 null
  })
}
```

修复：赋给局部常量

```ts
const v = value
if (v !== null) {
  someAsyncFn(() => v.toUpperCase())   // ✅
}
```

### 3. 类型断言会放弃收窄

```ts
const el = document.getElementById('x') as HTMLInputElement
el.value   // 不做 null 检查，运行时报错
```

## 常见错误

```ts
// ❌ 守卫返回 boolean 而不是类型谓词
function isUser(v: unknown): boolean { ... }
if (isUser(v)) v.name   // 报错：unknown 上没有 name

// ✅
function isUser(v: unknown): v is User { ... }
```

```ts
// ❌ 用 as 绕过而不是收窄
const data = JSON.parse(text) as User   // 运行时崩溃风险
```

::: interview 面试视角
能说清"回调中的收窄会失效，需要用局部常量"这一点，说明你实际遇到过这类编译错误，而不是只背手段清单。
:::
