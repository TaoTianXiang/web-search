## 回答框架

```
变化的事实 → 不变的能力 → 我的具体行动
```

避免两种极端：盲目乐观（"AI 只是工具，没影响"）与过度焦虑（"程序员要失业了"）。

## 变化的事实

| 能力 | AI 之前 | AI 之后 |
| --- | --- | --- |
| 写样板代码 | 耗时 | 几乎免费 |
| 记住 API 细节 | 有价值 | 价值大幅下降 |
| 手写常见算法 | 有区分度 | 失去区分度 |
| 翻译文档 / 写注释 | 耗时 | 很快 |

2026 的面试已经在调整（如你提到的清单）：

- 纯算法题权重下降（AI 一秒生成，失去区分度）
- 八股背诵权重下降（"告别八股"）
- 系统设计、工程实践、AI 运用权重上升

## 不变的能力（真正值钱的部分）

### 1. 判断力：知道"该做什么"

```
AI 能给出 5 种方案，但说不出"在你这个团队、这个业务、
这个时间窗口下，应该选哪个"。
```

判断力的来源：理解业务约束、理解团队能力、理解成本结构。

### 2. 问题定义能力

```
模糊需求 → 可执行的技术问题
"页面太慢" → "LCP 4.2s，主因是 TTFB 与主图未压缩"
```

AI 擅长"给定问题找答案"，不擅长"从模糊中提炼出正确的问题"。

### 3. 验证与兜底能力

```js
// AI 说"这样就可以了"
// 你需要知道：如何证明它真的可以
- 写什么测试能覆盖边界
- 看什么指标能确认没问题
- 出问题时如何快速定位
```

### 4. 系统与架构能力

```
单点代码 AI 很强；
跨模块、跨团队、跨时间的权衡，仍需要人。
（如：这个抽象三个月后会不会成为负担）
```

### 5. 沟通与推动能力

```
让五个团队接受一个方案，AI 做不到。
```

## 我的具体行动（示例表述）

> 1. **把 AI 用在"重复劳动"上**：样板代码、测试骨架、文档初稿。省下的时间投入到设计评审与性能治理。
> 2. **建立验证习惯**：任何 AI 产出都要过 typecheck + 单测 + 边界补测。
> 3. **深化系统能力**：今年重点补的是"如何量化架构决策的收益"，而不是记更多 API。
> 4. **保持对底层原理的理解**：AI 能写出 Proxy 响应式，但出了性能问题，仍要能解释"为什么这里要 shallowRef"。

## 关于"核心竞争力"的回答

不建议说"我比 AI 更懂代码"。更准确的说法：

| 维度 | 人的优势 |
| --- | --- |
| 上下文 | 了解业务历史、团队现状、隐性约束 |
| 责任 | 为决策后果负责（AI 不承担） |
| 判断 | 在信息不完整时做取舍 |
| 协作 | 推动他人接受方案 |
| 创造 | 提出新的问题，而不是回答问题 |

```
AI 把"实现"变成廉价，
于是"决定实现什么"和"验证是否真的实现了"变得昂贵。
```

## 常见错误回答

| 错误 | 为什么不好 |
| --- | --- |
| "AI 只是工具，没什么影响" | 忽视真实变化，显得不敏锐 |
| "程序员要失业了" | 消极且无行动方案 |
| "我会用 ChatGPT" | 太表层，没有方法论 |
| "AI 永远无法替代人" | 空泛，缺乏具体论证 |
